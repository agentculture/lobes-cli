# Delivery Summary — lane safety and quality (#304 #307 #308 #309)

plan: `lane-safety-and-quality-304-307-308-309` · run: `partial` · date: `2026-10-17`
baseline: `devague summary skeleton`

## Intent

> lobes lanes boot, compile and run safely: GPU services hold after a power cycle, the vLLM compile cache survives a recreate, a hot box sheds load instead of power-cycling, and clocks stay stock outside an explicit benchmark window

After: After a power cycle every lobes service waits until host uptime >= 120 s; a recreate reuses the lane's compile cache; a repeatedly crashing lane backs off instead of looping into held memory; a box over its per-card thermal threshold sheds sheddable tiers with 429 instead of heating further; lobes benchmark runs inside a locked-clocks window delegated to the machine CLI and always restores stock DVFS, recording conditions in the result

The run executed the 20-task plan `docs/plans/2026-10-17-lane-safety-and-quality-304-307-308-309.md`
in seven waves through `/assign-to-workforce`. The **Thor was code-only** throughout
(frame boundary c2): its experimental work was never deployed to, restarted or recreated.

## Mid-work Decisions

All five deviation records are `--origin llm` and still **proposed** — awaiting the operator's
`devague deviate --confirm`. They are quoted, not re-litigated:

- `d1` (proposed) — t14 additionally adds `LOBES_THERMAL_ZONES` / `LOBES_THERMAL_SHED_C` / `LOBES_THERMAL_RESUME_C` passthroughs to the fleet gateway service — Found by t13: the gateway service deliberately has no `env_file`, so without explicit passthroughs `thermal_c` is always None in the container. **Not implemented** (unconfirmed); tracked in #311.
- `d2` (proposed) — t15 records `host.conditions` on the single-model and `--all-lobes` results only — `measure`'s and `--profile`'s JSON contracts are keyed by role / profile name; adding a host key breaks both. Tracked in #312.
- `d3` (proposed) — t16's `doctor.py` change is more than the single registration call (flag, dispatcher, validation, `fix_plan.dirs`) — argparse flags and the `--fix` apply path live in `doctor.py`.
- `d4` (proposed) — t19 not run in this delivery; continues in #313 — needs d1 and explicit operator approval for a live, reset-prone Spark load (#304).
- `d5` (proposed) — t18 kept `tests/fixtures/upgrade_compat` unrefreshed — they are a *previous* scaffold; refreshing defeats the zero-byte upgrade test.

Decisions not covered by a deviation record:

- **Branch naming:** an old `agent/t5` branch from an earlier plan existed, so this run used `agent/ls-tN`.
- **Ledger location:** `.devague/` is tracked per branch. After a stray lapse was filed against PR-A's stale copy (reverted), every devague move ran on the bundle branch only.
- **Python 3.12 for gates:** worktree `uv run` defaulted to 3.13, where the pre-existing `test_the_engine_plumbing_is_gone_from_the_server_module` fails (3.13 dedents docstrings). Every merge gate used 3.12, matching the repo venv. The test bug itself is out of scope.
- **t8 mount target:** fixed at `/cache/vllm` with `VLLM_CACHE_ROOT` following the knob. The contract's original wording would have persisted the cache even when opted out. Within t8's acceptance criteria; the contract was corrected.
- **t12 watcher state file** is `<deploy>/.lobes-watcher-state.json` (`lane-state/` is likely root-owned), and the unit captures `PATH` at install time.
- **t14 latch** advances on request and `/status` reads, not on every 2 s sample.
- **Machine-CLI survey was stale:** scope finding s23 read local checkouts behind `origin/main` (lapse l3). The tasks were rebased onto `origin/main`, which already shipped power probes.
