Diagnosis (full responses captured):
  A  via spark -> forwarded to spark2 -> 404 {"message": "The model `primary` does not exist."}
     The forward rewrote `model` to the BACKEND name ("primary"), which no gateway accepts as a
     model id. Spec c20 had copied that convention from the pre-existing suffixed-lane path
     (review #252 "Finding 1"), and the t4 unit test asserted it — so the disagreeing-member
     lanes (`cortex-thor` style) had the same latent bug.
  E  via thor -> 508 proxy_loop, X-Lobes-Route-Reason: peer-less-loaded, Proxied-By: spark.
     On the non-hosting Thor, _peer_only_forward ran BEFORE the member-lane branch;
     infeasible_owner("cortex-spark2") falls back to the default model, so the name was
     pool-forwarded as plain cortex (to spark, origin tie-break), and spark correctly refused a
     hop-marked request naming a PEER lane.
  F  passed by accident: the same wrong pool path happened to pick spark.
  Also seen: spark's /v1/models listed `reranker-spark` although no reranker container runs on
  spark (#92 — listed must imply reachable).

Deviation d1 (approved by the operator, recorded via `devague deviate`, task t4, affects c20/h6):
  * forward the destination's announced served_id (role name fallback), never the backend name;
  * resolve member lanes FIRST in handle_post, before _peer_only_forward.
Plus (19e1ad9): /v1/models lists a member lane only if it can answer — self lane needs its
backend ready in the readiness snapshot, a peer lane needs the role in the peer's ready_roles.
