== how the render was applied ==
The Orin has no lobes CLI. `lobes init --shape orin-decider --profile orin` was rendered
on the Spark, from this branch, into a scratch copy of the Orin's deployment (deleted
afterwards). From that render ONLY these were copied onto the live box:
  docker-compose.yml        the gateway's decider passthroughs
  docker-compose.shape.yml  the decider-general service
  Dockerfile.decider, Dockerfile.decider-vllm
  .env  MODEL_GEAR_VERSION=0.86.0.dev639 (TestPyPI dev wheel of this branch),
        COMPOSE_PROFILES=decider,gemma2-embed,
        DECIDER_DOMAINS=general=http://decider-general:8000,
        DECIDER_DOMAIN_MODELS=general=culture-dev/clef-27b-GPTQ-W4A16-g64@4daaa224...
Render drift, NOT applied (the live values were kept):
  - the render rewrote GEMMA2_EMBED_MEM_LIMIT 8g -> 6g; the operator's 8g was kept
  - it would have replaced the live docker-compose.embed.yml, which is newer
    (parameterised) than the one this branch ships; the live file was kept
  - it wrote MODEL_GEAR_VERSION=0.86.0, not the dev pin
The HF cache was seeded from the verified local copy by hard links (16 files at
4daaa224, LFS by sha256, small files by git sha1); no weights were downloaded.

== boots: four failures, two fixes ==
boot 1 (dev638), 20:05: EngineCore OOM-killed by the 32g memory cgroup during CUDA-graph
  capture (anon-rss 32.5 GB). Cause: the sidecar's clef-vllm bundle step called
  snapshot_download(local_dir=...), which wrote an 18 GB REAL COPY of the weights inside
  the container; vLLM then logged "Available RAM: 0.06 GiB".
  Fix (2c92ec3, dev639): materialize_bundle() hard-links the HF-cache blobs (copies only
  across devices). Proven on the live box: the bundle's joint_head.safetensors and the
  local copy share inode 25203320, 3 links. vLLM then logged "Available RAM: 11.03 GiB".
boot 2 (dev639), 20:28: OOM-killed again at the 32g cap, at the start of CUDA-graph
  capture (cold torch.compile, 64 s; warm-up 129 s).
boot 3, 20:35: `docker restart`, compile cache warm (torch.compile 0.79 s, warm-up 16 s):
  OOM-killed again at 20:37:21, same point. A cold compile is therefore NOT the cause.
  Cgroup memory.stat at that kill: kernel 31,348,162,560 B (on the Jetson the GPU
  allocations are charged as kernel memory), anon 3,007,512,576 B, file 102,400 B.
  vLLM's own budget at util 0.40 is 24.54 GiB.
  The engine arguments were identical to the plain-run container that booted
  (non-default args compared line by line). Left to vLLM, the KV pool is sized from the
  board's free memory, which moves with the neighbouring lanes and the page cache: the
  plain-run container got 94,890 tokens on one boot and 131,072 on another, same
  settings.
  Fix (7e4f38d): new optional decider domain key kv_cache_memory_bytes ->
  DECIDER_KV_CACHE_MEMORY_BYTES (the sidecar already read it); orin-decider pins 4 GiB.
